# Custom Features Synchronous Maintenance Rule

Whenever adding, updating, or repairing any feature, bug fix, or UI adjustment in this repository (`Privatexiao/wosbot`) that differs from or extends upstream (`Shederator/wosbot`):

1. **Source of Truth**: Treat [`docs/custom-features.md`](../../docs/custom-features.md) as the authoritative inventory of differences from upstream. Confirm differences from code or Git history rather than relying only on commit messages.
2. **Synchronous Documentation Update**: Update the inventory in the same change. Describe upstream behavior, custom control flow, related configuration, fallback or safety boundaries, affected files, and the evidence actually verified.
3. **Lifecycle Accuracy**: Cover additions, behavior changes, bug fixes, removals, and features that have become equivalent upstream. Do not leave stale entries or claim unperformed verification.
4. **Integrity Is Mandatory**: Preserving every custom feature in the inventory is a hard acceptance criterion for any upstream merge, rebase, cherry-pick, module migration, or conflict resolution. The merge is incomplete while any listed behavior is missing or its preservation is unknown.
5. **Conflict Resolution Workflow**: Never resolve a custom/upstream conflict by blindly selecting `ours`, selecting `theirs`, or deleting the custom side. Inspect both implementations, understand the upstream structural or API change, and port the custom behavior into the new upstream structure. Preserve configuration keys and defaults, UI entry points, templates/assets, persistence and migrations, scheduling/preemption behavior, fallback and safety logic, logs, and tests.
6. **Post-Merge Audit**: After integration, audit every item in `docs/custom-features.md` against the merged code and run the relevant tests or behavioral checks. Record actual evidence and explicitly report saved-frame or live-account verification that remains outstanding. Do not declare the merge complete based only on conflict-free compilation.
7. **Removal Requires Authority**: Do not remove, disable, narrow, or replace a custom feature without the user's explicit authorization. Verified equivalent upstream behavior may replace the custom implementation only when it preserves the same user-visible capability, configuration compatibility, and safety guarantees; document that item as upstreamed.
8. **No Unrequested Git Push**: Never run `git push` unless the user explicitly requests to commit and push changes (`提交推送git`).
